# sugar_sync_google_calendars
複数のGoogleカレンダーを同期するためのGoogle Script

## How to use it
- スクリプトは**同期先（予定を書き込む側）のGoogleアカウント**で実行する。
- 同期元のカレンダーを、同期先のアカウントに「予定の表示（すべての予定の詳細）」で共有しておく。「空き時間情報のみ」では予定を取得できない。（参考：https://support.google.com/calendar/answer/37082?hl=ja ）
- 同期先のアカウントでGoogle Apps Scriptのプロジェクトを作成し、Google Apps Script APIを有効化しておく。
- consts.jsを自身の設定に合わせて修正をしておく。（consts.jsの修正は原則commitしないこと）
- 後述するclaspによりデプロイを行うこと。

## 予定の公開に関して
- `PRIVATE_PLAN`をtrueにしておくと他人からは予定の詳細を見られないようにできるので、企業内で利用するGoogleアカウントでは原則trueを使うことを推奨。
  - true: 同期先には `🙅‍♂️ Block_<同期元Key>_synced` というタイトルの非公開予定が作成される。説明欄には同期元の予定を識別するハッシュが入る。
  - false: 同期元のタイトルに `_<同期元Key>_synced` を付けたタイトルで公開予定が作成される。説明欄には元の説明と参加者のメールアドレスが入る。

## 予定同期の仕様

### 同期の対象期間
- 実行日の0:00から`SYNC_DAYS`日後の23:59までの予定が対象。日付の区切りはApps Scriptプロジェクトのタイムゾーン（`appsscript.json`の`timeZone`）に従う。

### 同期から除外される予定
同期元の予定のうち、以下のいずれかに当てはまるものは同期されない。

| 条件 | 内容 | 例 |
|---|---|---|
| 終日の予定 | 開始時刻・終了時刻が設定されている予定のみ同期する | 終日の「休暇」 |
| 1分ずらした時刻 | 開始時刻が`xx:01`・`xx:31`、または終了時刻が`xx:29`・`xx:59`の予定。15分単位など、それ以外の時刻は同期する | 12:01〜13:00、12:00〜14:59 |
| タイトルのプレフィックス | `info_`、`非同期_`、`todo_` | `info_ランチ` |
| タイトルのサフィックス | `_info`、`_非同期`、`_todo` | `ランチ_非同期` |
| 自分宛てに同期された予定 | タイトルが`_<自分のKey>_synced`で終わる予定。相互同期したときに予定がループしないようにするため | `🙅‍♂️ Block_movus_synced` |
| 不参加の予定 | 同期元で「不参加」と回答している予定 | |
| 同じ時刻の予定がすでにある | 同期先に開始・終了時刻が完全に一致する予定がすでにある場合は作成しない（同期で作った予定かどうかは問わない） | |

※ 「自分のKey」は、スクリプトを実行しているアカウントのメールアドレスに`KEY_EMAIL_PAIRS`で対応づけたKey。

### 予定が変更・削除された場合
- 実行のたびに、同期先にある同期済みの予定と同期元の予定を突き合わせ、同期元に対応する予定がなくなったものを同期先から削除する。
  - 同期元の予定が削除された場合
  - 同期元で「不参加」に変更した場合
  - 同期元の予定があとから上記の除外条件に当てはまるようになった場合（例: 開始時刻を12:01にずらした）
  - 同期元の時刻やタイトルが変わった場合。古い予定を削除し、新しい内容で作り直す（時刻が同じでタイトルだけ変わった場合は、次の実行で作り直される）
- 削除されるのは同期で作成した予定のみ。以下の予定は削除しない。
  - タイトルが`_synced`で終わらない予定（`PRIVATE_PLAN=true`の場合は、`🙅‍♂️ Block_`で始まり説明欄にハッシュを持つ予定のみが対象）
  - 自分以外に、不参加でない参加者がいる予定

## Remarks
- 複数アカウント間で、相互に同期したい場合はそれぞれのGoogleアカウントで上記の設定が必要となっている。また、相互に設定した場合でも問題なく運用できるように設計している。
- 3つ以上のアカウントがある場合でも、すべてのペアに対して設定をしないといけないわけではない。メインのアカウントを決めておいて、メインのアカウントと各サブアカウント同士で同期の設定を行っておけばよい。

## claspによるGoogle App Scriptのデプロイ

### 前提条件
- Node.jsがインストールされていること
- Google Apps Script APIが有効化されていること（https://script.google.com/home/usersettings ）

### 初回セットアップ

#### 1. claspのインストール
```bash
make prepare
```
または
```bash
npm i @google/clasp -g
```

#### 2. Googleアカウントでログイン
```bash
make login
```
または
```bash
clasp login
```
ブラウザが開くので、**スクリプトを実行するアカウント（同期先のアカウント）**でログインし、claspへのアクセスを許可してください。

#### 3. Google Apps Scriptプロジェクトのクローン
Google Apps Scriptのプロジェクトを作成済みの場合、スクリプトIDを使ってクローンします。`workspace/`ディレクトリがない場合は先に作成してください（`.gitignore`対象）。
```bash
mkdir -p workspace
make clone id=<your_script_id>
```
または
```bash
cd workspace
clasp clone <your_script_id>
```

**スクリプトIDの取得方法:**
1. Google Apps Scriptのエディタを開く（https://script.google.com/ ）
2. 対象のプロジェクトを開く
3. 「プロジェクトの設定」（歯車アイコン）をクリック
4. 「スクリプトID」をコピー

エディタのURL `https://script.google.com/home/projects/<スクリプトID>/edit` からも確認できます。

### デプロイ方法

#### 1. consts.jsの設定
`files/consts.js`を自身の環境に合わせて編集します。

変数名と実際の役割が逆になっているので注意してください。`SOURCE_CALENDAR_KEY`が**予定を書き込む側**、`DEST_CALENDAR_KEYS`が**予定を読み取る側**です。
```javascript
// 予定を書き込むカレンダーのKey（スクリプトを実行するアカウント）
const SOURCE_CALENDAR_KEY = 'sample01';

// 予定を読み取るカレンダーのKey（複数指定可能）
const DEST_CALENDAR_KEYS = ['sample02', 'sample03'];

// 同期する日数
const SYNC_DAYS = 30;

// プライベートモード
const PRIVATE_PLAN = true;

// KeyとEmailのマッピング
const KEY_EMAIL_PAIRS = [
  ['sample01', 'sample-01@sample.com'],
  ['sample02', 'sample-02@sample.com'],
  ['sample03', 'sample-03@sample.com']
];
```
Keyは同期先の予定タイトル（例: `🙅‍♂️ Block_sample02_synced`）に表示されるので、他人に見えても問題ない名前にしてください。

#### 2. デプロイの実行
```bash
make deploy
```

#### 3. 初回の手動実行
1. Google Apps Scriptのエディタを再読み込みし、`main.js`を開く
2. 実行する関数で`syncCalendarEvents`を選び、「実行」をクリック
3. 権限の確認が表示されたら、スクリプトを実行するアカウントで承認する
4. 実行ログと同期先のカレンダーで、予定が作成されていることを確認する

#### 4. トリガーの設定
Google Apps Scriptのエディタで以下の手順でトリガーを設定します:
1. Google Apps Scriptのエディタを開く
2. 左メニューの「トリガー」（時計アイコン）をクリック
3. 「トリガーを追加」をクリック
4. 以下の設定を行う:
   - 実行する関数: `syncCalendarEvents`
   - 実行するデプロイ: `Head`（`make deploy`後も設定し直さずに最新のコードで動く）
   - イベントのソース: `時間主導型`
   - 時間ベースのトリガー: `分ベースのタイマー` → `15分おき`（または任意の間隔）
   - エラー通知設定: `毎日通知を受け取る`（推奨）
5. 「保存」をクリック

左メニューの「実行数」で、トリガーによる実行が「完了」になっていることを確認できます。

### トラブルシューティング

#### Apps Script APIが有効になっていないエラー
```
User has not enabled the Apps Script API.
```
→ https://script.google.com/home/usersettings にアクセスして「Google Apps Script API」を有効化し、数分待ってから再試行してください。

#### ログインエラー
```bash
make login
```
を実行して再ログインしてください。

#### 予定が同期されない
- 同期元のカレンダーが「予定の表示（すべての予定の詳細）」で共有されているか確認してください。共有されていない場合、エラーにならずに何も同期されません。
- 実行ログに`Skipped ...`と出ている場合は、「同期から除外される予定」の条件に当てはまっています。

#### デプロイ確認
デプロイ後、Google Apps Scriptのエディタで各ファイルが更新されていることを確認してください。`clasp push`で`Script is already up to date.`と表示された場合は、すでに最新のコードが反映されています。
